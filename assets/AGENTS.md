# AGENTS.md — assets/ 建模规范（Blender → GLB → Godot）

本目录下所有资产都由同目录的 Python 脚本在 Blender 里**程序化生成**，再导出 `.glb` 给 Godot 4 使用。
脚本是唯一事实来源：`.blend` / `.glb` / `*_preview.png` 都是产物，**改模型请改脚本再重新生成，不要手改产物**。

本文件的核心目的只有一个：**让所有模型保持统一的真实尺度（米）**，这样在 Godot 里摆放时不需要为每个资产单独调 `scale`。

---

## 1. 硬性尺寸约定（所有新建模必须遵守）

| 约定 | 值 | 说明 |
| --- | --- | --- |
| 单位制 | **公制** | `scene.unit_settings.system = 'METRIC'` |
| 单位比例 | **1 Blender unit = 1 米** | 不要用 `unit_settings.scale_length` 去缩放，直接按米建模 |
| 世界朝向（Blender） | **+Z 向上** | 与 Blender 默认一致 |
| 导出朝向（Godot） | **+Y 向上**（`export_yup=True`） | glTF 自动做 Z-up → Y-up；Godot 中"树往上长"= `+Y` |
| 地面基准 | **根部 / 地面 = z = 0** | 树干底、草根、假茎底必须正好落在 z=0，不许悬空或埋地 |
| 物体缩放 | **全部 apply 为 1** | 导出前 `transform_apply(scale=True, rotation=True)`，禁止用物体 scale 假装尺寸 |
| 原点 | **放在"摆放锚点"上** | 见 §4，Godot 里 `position` 直接等于落地点 |
| 网格尺寸容差 | ±2% | 与下表基准值的偏差不超过 2%，改款必须同步更新表格 |

> ⚠️ 最关键的一条：**不要让 Godot 侧的 `scale` 来救尺寸**。所有资产都必须是 1:1 米制，
> 组件脚本（如 `components/vegetation/banana_tree/banana_tree.gd`）是按真实米数做几何计算的。

---

## 1.1 关于"用约束统一大小"：能做，但不是本项目的机制

社区建议里常见的做法是加 **复制缩放（Copy Scale）** 约束，让所有模型跟随一个"标准参考物"的缩放。
本仓库实测（Blender 5.2）后确认：**这条链路能工作，但会把缩放烘焙成导出节点的 scale，和 §1 的"scale 恒为 1"冲突**，
所以本项目**不把它当作尺寸统一手段**，只保留它作为建模期的临时对齐辅助。

### 实测结论（可复现）

在 Blender 5.2 + glTF 导出（`export_apply=True, export_yup=True`）下：

| 观察 | 结果 | 含义 |
| --- | --- | --- |
| 约束是否影响 `ob.scale` | **不影响**，`ob.scale` 仍是 `(1,1,1)`，只有 `matrix_world` 变了 | 约束是求值期效果，不改属性 |
| 导出时是否生效 | **生效**，`matrix_world` 被分解进 glTF 节点 | 约束结果会被烘进 `.glb` |
| 导出到 Godot 里长什么样 | 节点带 `"scale": [0.5, 0.5, 0.5]` | **变成 Godot 侧的 `scale`，正是我们要禁止的东西** |
| 尺寸不匹配时是否被"修正" | **不会** | 见下面的"比例系数 ≠ 绝对尺寸" |

复现脚本（可直接粘进 Blender 脚本编辑器运行）：

```python
bpy.ops.mesh.primitive_cube_add(size=1.0);  REF = bpy.context.active_object
bpy.ops.mesh.primitive_cube_add(size=10.0); BIG = bpy.context.active_object
c = BIG.constraints.new('COPY_SCALE'); c.target = REF; c.use_make_uniform = True
REF.scale = (0.5, 0.5, 0.5)
# 结果：BIG.matrix_world 缩放 = 0.5 → 导出 glTF 后 BIG 节点 scale = [0.5,0.5,0.5]
# 但 BIG 的网格仍是 10 m，Godot 里读到的尺寸 = 10 × 0.5 = 5 m，与 REF 的 0.5 m 仍不一致
```

### 正确用法与边界

- ✅ **能做**：让一组物体在建模期共享同一个缩放系数（改一个参考物，全体同步缩放）。
  `use_make_uniform`（UI 里的"统一/使一致"）**只对非均匀参考缩放有意义**：参考物 `(1,2,1)` 时，
  关闭它 → 子物体也被拉成 `(1,2,1)`；开启它 → 子物体取各轴平均得到 `1.26` 等比缩放。
  参考物本身是等比缩放时，这个开关没有效果。
- ❌ **不能做**：修正"网格数据本身就差了 100 倍"。约束只是比例系数，
  1 m 的方块和 10 m 的方块都挂着 Copy Scale，永远不会因此变得一样大。
  **真实尺寸只能靠建模时按米写参数 + §2 基准表来保证**（这一点与用户意见的"重要提醒"完全一致）。
- ❌ **本仓库不用它导出**：它会往 `.glb` 节点里写非 1 的 `scale`，让 Godot 侧出现隐藏缩放，
  后续改资产时极易踩坑（改网格尺寸却没改参考物，缩放突然变化）。
- ⚠️ 约束**不做静默清理**：如果只是把模型挂在参考物下拖进场景做视觉比对，用完必须删除约束并在导出前把物体移出参考物层级，
  否则导出时对象树里会混进参考物（不是目标资产）。

### 补偿 "Child Of" 只跟随位置/旋转

若确实要建模期跟随（不参与导出），用 **子级（Child Of）** 约束并把缩放轴向关掉。注意属性默认值与直觉相反：

```python
c = ob.constraints.new('CHILD_OF'); c.target = REF
print(c.use_location_x, c.use_rotation_x, c.use_scale_x)   # True True False  ← 缩放默认就是关的
```

实测 Blender 5.2 中 `CHILD_OF` 的 `use_scale_x/y/z` **默认即为 False**，
所以"只勾位置和旋转、取消缩放"通常无需手动改；但**不要依赖默认值**，
在脚本/清单里显式置位更安全。另外 `CHILD_OF` 使用 `inverse_matrix` 做偏移补偿，
是"相对当前变换"的跟随，不是真正的父子层级。

> **一句话结论**：约束解决的是"建模期同步调比例"，基准表 + 脚本里的米制参数解决的才是"绝对尺寸一致"。
> 本项目以**后者**为准，前者只在 Blender 里做临时视觉对齐，**导出前必须清干净**。

## 2.1 带内置动画的资产（猴子）

`assets/models/monkey/low_poly_monkey.py` 是本仓库**第一个带角色动画**的资产，
它确立了后面所有带动画资产的导出套路。

### 骨架方案：节点层级，不用 armature 权重

每个肢体是**独立网格物体**，物体原点就落在关节枢轴上，按关节父子挂接：

```
MonkeyRoot → Monkey_Hips → Monkey_Torso → {Monkey_Head → Monkey_Ear_R/L,
                                              Monkey_Arm_R/L_Upper → Fore → Hand → Fingers}
                                → {Monkey_Leg_R/L_Thigh → Shin → Foot}
                   → {Monkey_Tail_1 → Tail_2 → Tail_3}
```

动画 = 关键帧这些物体的**局部变换**，导出 glTF 后 Godot 的 `AnimationPlayer`
直接就能播。好处是彻底绕开权重、骨骼命名、骨骼 rest pose 这几类跨软件最容易翻车的东西；
代价是网格之间靠"互相插进去"藏接缝（关节处留一段重叠），不是焊接成一整块。

> ⚠️ 所以 §4「导出前把世界变换烘进网格并归零」这条**对带动画的资产不适用** ——
> 一旦把枢轴烘进网格，动画就没有可转的关节了。带动画的资产保留各物体的
> 局部变换（`export_apply=False`），但**每个物体的 scale 仍必须是 1**（§6.7 那条校验照跑）。

### ⚠️ 导出动画片段：Blender 5.2 的实测坑

**`export_animation_mode='NLA_TRACKS'` 在 Blender 5.2.2 上导不出东西** ——
NLA strip 根本不驱动物体变换（`frame_set` 之后物体纹丝不动），导出结果 0 条动画。
**要用 `'ACTIONS'`**，但它只认两种来源：

1. 物体身上的 **active action**；
2. 物体身上的 **NLA track 里的 strip**（检查的是 `strip.mute`，**不是** `track.mute`）。

于是做法是：**每个物体挂 N 条同名 NLA track**（名字 = 片段名），导出器按 track 名
把各物体的动画合并成一条 glTF animation。

```python
track = ad.nla_tracks.new()
track.name = name                      # 片段名 = 合并依据
strip = track.strips.new(name, 0, act)
strip.action_slot = slots[nm]          # ⚠️ 必须显式指向"本物体在这个 Action 里的 slot"
```

三个必踩的坑：

- **`strip.action_slot` 必须显式赋值**，否则导出器找不到对应的 channelbag，**整个片段被丢掉**。
- **track 可以静音，strip 不能静音**。track 静音 → `.blend` 打开时角色是静止站姿；
  strip 静音 → 导出时片段直接消失。
- **同名 Action 必须先清干净**。脚本里建的 Action 带 fake user，`clear_scene()` 不会删它，
  下一轮新建同名 Action 会被 Blender 加后缀（`Monkey_Run.001`），**Godot 里的动画名就变了**。
  所以建模脚本开头要 `for a in list(bpy.data.actions): bpy.data.actions.remove(a)`。

### 角色动画也要过"地面审计"

脚本末尾的 `clip_ground_audit()` 会逐片段采样每一帧，算出**脚底最低点**。
判定标准：站立姿势 `min z = 0`，动画过程中允许 ≤ 3 cm 的瞬时穿模。

跑动循环尤其容易穿地，因为"脚掌最低点"会随脚掌倾斜而变（脚尖下压时最低点是脚尖）。
脚本里用 `crouch_depth()` / `stance_offset()` / `_run_hips_height()` **按几何反解髋部高度**，
而不是手填角度 —— 手填的角度必然穿地（早期版本脚底插进地面 7 cm，就是这个审计抓出来的）。

**脚底最低点要用椭圆的"支撑函数"精确算**，别拿"脚尖 / 脚跟的高度"去估：

```
椭圆 (中心 cy,cz；半轴 ry,rz) 绕 X 转 phi 之后
    z_min = cy·sinφ + cz·cosφ − √((ry·sinφ)² + (rz·cosφ)²)
```

脚掌 = 脚掌椭圆 + 脚趾椭圆 + 踝关节球，三者取 min（`foot_lowest_z()`）。
差别很实：只拿脚尖/脚跟估，跑动循环脚底插进地面 **1.8 cm**；换成支撑函数后是 **0.0 cm**。

**跑动的髋高要取两条腿需求的 `max`**，不是只按支撑腿算。跑动里有"两脚同时着地"的
错身位：蹬离那条腿脚尖扎地、要的髋比另一条腿高 2 cm，只按触地腿算，
蹬离那只脚就会插进地面 —— 还是 `clip_ground_audit()` 抓出来的。

### 2.2 卡通角色的形体做法（猴子第四轮定稿）

猴子前三轮分别栽在"方盒子拼的猿"、"部件各拼各的、互相不协调"和
"脸是一张惨白面具、身子又细又长"上。第四轮定稿的结论：
**配色照参考图采样；脸和毛画在同一个曲面上；关节靠球 + 锥台；尾巴靠弧段。**

用了 5 个形体工具（都在 `low_poly_monkey.py` 里，后面做卡通角色可以直接抄）：

| 工具 | 干什么 | 关键点 |
| --- | --- | --- |
| `ellipsoid()` | 低多边形椭球（UV 球，平面着色），支持**逐面换色** + **basis**（把三个轴映射到世界方向）+ **deform**（改写顶点） | `color_fn(面中心, 面法线, 方向) -> (槽名, 颜色)`；`方向` 是该面在球面上的参数方向，分色规则按它算 |
| `ball()` | **低多边形球**（各向半径相同） | 关节专用；`segs` 要和管的棱数一致，棱面走向才对得上 |
| `tube()` | 两点之间的 n 棱锥台 | 脖子 / 四肢；**四肢用 12 棱圆管** |
| `tube_path()` | 沿一条**折线**包 n 棱管（半径可逐点变） | 嘴巴 / 眉毛 / **尾巴的弧段** |
| `spike()` | 四棱锥 | 头顶呆毛 |

### 关节必须是球，而且管子要从球里"长出来"

低模角色最容易翻车的地方就是关节。之前猴子用"棱柱管直接怼棱柱管"，
结果每个关节都是一道**硬折角**，渲染出来像竹节、完全不像卡通角色。

三条规则（照抄即可）：

1. **每个关节放一个 `ball()`**：肩 / 肘 / 腕 / 胯 / 膝 / 踝 / 颈，一个不落。
2. **管的半径要比球小**（球 ≈ 管的 1.1~1.2 倍），并且管的起点**埋进球里**——
   这样棱柱的平端盖被球挡住，轮廓是连续的圆，不是两个棱柱对撞。
3. **球和管的棱数一致**（都用 12），否则球面和管面的棱线错开，接缝处会出现一道折痕。

```python
def build_upper_arm():
    b = MeshBuilder()
    ball(b, (0.0, 0.0, 0.010), 0.054, SLOT_FUR, PAL["fur"], segs=12)   # 肩关节
    tube(b, (0.0, 0.0, 0.012), (0.0, 0.0, -UPPER_ARM_M), 0.048, 0.038, 12,
         SLOT_FUR, PAL["fur"])                                          # 从球里长出来
    return b
```

> 顺带一提：**枢轴要落在身体表面上**。肩关节的枢轴正好在躯干侧面，
> 球一半在躯干里、一半在外面，才像"肩膀从身体长出来"；
> 枢轴埋进去太深，球就整个消失，肩膀又变回一个硬角。

### 配色必须照参考图采样，不能凭感觉

这是第三轮翻车最直接的原因：参考图的脸是 **暖橘棕**（0.90 / 0.68 / 0.45），
脚本里却写成了**奶白**（0.95 / 0.84 / 0.68），渲染出来就是一张惨白面具，
跟参考图完全两回事。采样方法（不用装 PIL，直接问 Blender）：

```python
img = bpy.data.images.load("reference.jpeg")
img.colorspace_settings.name = 'Non-Color'      # 读原始 sRGB 数值，别读线性值
px = list(img.pixels)
def sample(x, y_top):                            # y 从上往下数
    i = ((img.size[1] - 1 - y_top) * img.size[0] + x) * 4
    return tuple(round(px[i + k], 3) for k in range(3))
```

采完直接写进 `PAL`，再 `srgb2lin()` 转线性空间（§6.6）。

### 脸盘要按"发际线"分色，不是按椭圆切

参考图的脸不是一块贴在颅骨外的"皮"，而是**同一个曲面上分出的两片颜色**：
棕色毛帽盖住头顶 + 脑后，暖橘色脸盘是前下方的一大片。

分界线（发际线）要按**仰角**量。直接在 x/z 平面上切椭圆，边界在脑袋两侧是两条
**竖直硬边**，渲染出来像往脸上糊了张面具。而且发际线**不是一条平的线** ——
正前方高、往两侧一路压到下颌，正视图是"额头一道横线"，侧视图是"额头斜着压到吻部"，
**同一个公式两边都对**：

```python
HAIR_EL = 0.50            # 发际线基准仰角（额头正前方）
HAIR_DROP = 0.75          # 往两侧压下去多少
HAIR_AZ_LIMIT = 1.62      # 超过这个方位角（耳后）全是棕毛

def _head_color(ctr, nrm, d):
    el = math.asin(max(-1.0, min(1.0, d.z)))
    az = math.atan2(d.x, d.y)
    k = min(1.0, abs(az) / HAIR_AZ_LIMIT)
    h = HAIR_EL - HAIR_DROP * k * k
    h += 0.055 * math.sin(2.3 * az + 0.6) + 0.035 * math.sin(5.1 * az + 2.0)
    if el > h or abs(az) > HAIR_AZ_LIMIT:
        return SLOT_FUR, PAL["fur"]
    if abs(az) < 0.115 and el > -0.05:     # 额头正中的"中缝"
        return SLOT_FUR, PAL["fur_d"]
    return SLOT_TAN, PAL["tan"]
```

### 吻部用 deform 前突，不要外挂一个球

参考图侧面：额头是圆的，但下方**鼓出一个尖吻**，嘴和鼻孔都在吻上。
外挂一个球会在下巴处留下一块诡异的浅色斑；改成**给椭球加一个变形**，
是同一个曲面，分色自然跟着走，边界不会生硬：

```python
MUZZLE_DIR = Vector((0.0, 0.94, -0.34)).normalized()   # 吻的正前方（朝前偏下）
MUZZLE_ANG = 0.70          # 吻部影响半角（弧度）
MUZZLE_FWD = 0.060         # 吻部前突量（米）

def _head_deform(d, p):
    ang = math.acos(max(-1.0, min(1.0, d.dot(MUZZLE_DIR))))
    if ang >= MUZZLE_ANG:
        return p
    m = 1.0 - (ang / MUZZLE_ANG) ** 2
    p.x *= (1.0 - 0.18 * m)          # 吻部比脑袋窄
    p.y += MUZZLE_FWD * m
    p.z -= MUZZLE_DOWN * m
    lo = max(0.0, -d.z)              # 下半颗头收窄：脸是"上宽下尖"，不是鸡蛋
    p.x *= (1.0 - 0.20 * lo * lo)
    return p
```

### 脸部的零件全靠"沿曲面采样 + 扁盘/细管"

- **眼睛**：眼白压成**贴在脸上的扁盘**（薄轴沿法线）。用球体嵌进曲面，轮廓会被
  切出不规则的怪形状。瞳孔是**贴在眼白表面的另一片扁盘**，占眼白直径的一半
  （参考图 5~6 成），再点一颗高光。
- **耳朵**：耳窝用**逐面分色画在耳廓同一个曲面上**，不要外挂浅色球 ——
  外挂会和耳廓正面重合，渲染出来是一道道条纹（Z-fighting）。
- **嘴巴 / 眉毛**：先在曲面上一段段采样出折线，再用 `tube_path()` 包成管。
  直管拼不出弧线，嘴必须是弧。
- **鼻孔**：两片极小的扁椭球。

### 尾巴每段做成圆弧，不是直管

三根直管接起来是"竹节"，参考图那条尾巴是**一条平滑的大 S 钩**。
做法：每段是一段二次贝塞尔弧，**起点切线比 −Y 低 20°、终点抬 20°**，
于是每段自转 40°；关节处再补 −40°，接缝的切线就对上了，看不出折角。

```python
p1 = Vector((0.0, -0.500 * ln, -0.182 * ln))    # 控制点在弦下方 → 弧向转弯内侧凹
p2 = Vector((0.0, -ln, 0.0))
pts = [p1 * (2 * u * (1 - u)) + p2 * (u * u) for u in (k / 8.0 for k in range(9))]
tube_path(b, pts, radii, 12, SLOT_FUR, PAL["fur"])
```

### 写这层东西时踩到的坑（都是渲染出来才发现的）

1. **手臂"外张"是绕 Y，不是绕 Z**。手臂是垂着的（几何朝 −Z），绕 Z 转根本转不动它 ——
   写错的话手臂会一直缩在躯干里，只剩两只手浮在腰边。
2. **躯干要比肩窄**，否则手臂整条埋在身体里。参考图躯干宽 0.23 m / 肩宽 0.14 m，
   手臂要外张 10° 才露得出来。
3. **尾巴卷起来不能插进脑袋**。头底在 z≈0.49，尾尖要停在那以下、或者停在脑袋轮廓外
   （|x| > 0.16），否则尾尖会从脸里穿出来。
4. **IK 的 pole 向量决定肘往哪边支棱**。鼓掌这种"手要凑到中线"的动作，
   pole 给成朝外（`(±1, 0, -0.4)`）肘会支棱成两只大翅膀；给成朝下（`(±0.2, 0, -1)`）
   才是"肘下沉、双手在胸前拍"的自然姿势。
5. **耳朵要又大又圆**。第二版把耳朵做成"正对镜头的扁圆盘"，像两只卫星天线；
   第三版改太小，耳廓整个陷进脑袋里，读起来像个"窟窿"。定稿：直径 ≈ 颅高的 3 成，
   耳根埋进颅骨、**耳廓明显凸出侧影**，耳窝是耳廓中间一小块橘色。
6. **手脚用比脸略暗的橘色**。跟脸同色时，手脚在阳光下会白得像戴了手套。
7. **参考图的头比宽要高**（正面量：宽 143 px、高 165 px）。做成正圆球会太"方"，
   `HEAD_R` 的 X 要比 Z 小一大截。
8. **身体要"圆而深"**。参考图侧视里躯干几乎是个球（深 ≈ 宽），
   做成细长的桶形会立刻变成"瘦长猿"。

另外：**接触表的采样帧要避开周期**。发抖是 5 Hz，采样帧间隔超过 0.2 s 就是同一个相位，
三张图会一模一样（看起来像没做动画）。猴子现在取 1 / 4 / 8 帧。

| 发际线 | 单调下降的斜线 | **W 形**：正中的褐毛楔形压到眉心（el +0.52），两侧夹出 el +0.70 的橘色脸颊 | 用 `HAIRLINE` **表**驱动（见下），单值函数描述不了 |

#### 发际线要按"射线扫描"量，不能靠看图猜

发际线是**一条空间曲线**（不是一条水平线），从正面看是 W 形，从侧面看是斜线。
量它的办法：拿参考图，从**颅心**往外沿一条条射线（固定仰角 el，扫方位角 az），
打印每条射线上的"橘色/褐色"序列，边界就出来了。本仓库实测（正面视图）：

| 仰角 el | 橘色区间（方位角） |
| --- | --- |
| 5° | 0.20 – 1.05 |
| 15° | 0 – 1.40 |
| 25° | 0 – 1.00 |
| 35° | 0.25 – 0.80 |
| 45° | 全褐 |

于是发际线（褐色上边界）= 一张**表** `HAIRLINE = [(|az|, el), ...]`：
`(0.00,0.520) (0.10,0.580) (0.20,0.635) (0.30,0.665) (0.45,0.690) (0.60,0.700)
(0.70,0.690) (0.80,0.560) (0.90,0.450) (1.00,0.350) (1.15,0.270) (1.40,0.200) (1.70,0.000)`
再配一条"橘色面盘的侧边界" `face_az_limit(el)`（el=0 处 az 1.06，el>0.35 快速收回）。

#### 写这只猴时踩到的坑

1. **材质槽编号必须重映射**。网格里按"用到哪些材质"排序后再 append，
   `material_index` 要用**排序后的下标**；直接 append 全调色板再按调色板下标赋值，
   每个面都会拿到错的颜色（脸会变成一片深褐）。
2. **局部坐标 ≠ 世界坐标**。按面分色的函数里如果拿世界常量（`HEAD_C`）去减局部顶点，
   方向永远算错，肚皮/脸盘的斑块就整块消失（实测脸全变褐色）。
3. **分色规则必须用"未变形"的球面方向**。参考图那种"同一个曲面上分出两片颜色"的画法，
   分色依据是**球面方向 d**，不是变形后的顶点位置：吻部的 deform 会把前下方的顶点
   往前推，用顶点反算方向会把仰角算低 **0.1 rad**，发际线整体下移一大块。
   所以 `ellipsoid()` 把面心的球面方向直接传给 `mat_fn`。
4. **分色还要用面心的方向，不是第一个顶点的方向**。用第一个顶点会让每条颜色边界
   整体偏到"上一圈纬度"上去，发际线会比设计值高整整一圈棱面。
5. ⚠️ **低模球面必须用"四边形"建，不能拆成三角形**。拆三角形会在每个格子的对角线上
   留下一条**着色折痕** —— 头和身子看上去全是毛刺，而且每条颜色边界都变成锯齿。
   一格四边形 = 一个平面法线 = 一块干净的板面，和参考图一致。
   同时**绕序要保证法线朝外**：`(i,j) → (i+1,j) → (i+1,j+1) → (i,j2)`，
   极点用三角扇（`grid[0][0]` 那个点），别再拿极点那一整圈退化三角形充数。
6. **五官要"贴"在真正的多边形表面上，不能贴在理想球面上**。
   低模头的平面比理想球面**低最多 2.6 mm**，按理想球面摆的眼睛会浮在脸上、
   眉毛和嘴会悬空。做法：先用 `FacetedSurface` 把射线打到**平面**上拿到真实表面点，
   再把五官压进那个表面一点（`fs_path()` 的 `sink` 参数）。
7. **但"投影到平面"对小于一个棱面的东西会失真**（一只眼睛比一个颅骨棱面还小，
   投影会在棱面之间跳，轮廓被啃出豁口）。所以**眼白/瞳孔/高光改成多边形贴片**：
   贴片自己的轮廓就是干净的 n 边形，不被颅骨棱面切割；
   每个顶点再**抬过当地棱面的深度**，保证颅骨不会从贴片里穿出来。
8. **眼球要压成球冠，不是圆锥**。圆锥会让瞳孔支棱成一根刺，侧面看两只眼睛是分离的；
   球冠（`cap_height()`）的曲率半径给 0.30 m 就是浅浅一个鼓包，像参考图那样。
9. **贴片的层与层要"平行偏移"**：瞳孔 = 眼白球冠 + 0.8 mm，高光 = 瞳孔 + 0.8 mm。
   每层各做一个锥，层与层会互相穿插。
10. **耳朵的网格要建在物体原点**，位置靠物体 `location` 给；
    网格里再写一遍耳心位置 = 位置算了两遍，耳朵会飞到脑袋外面去。
11. **尾巴三段的父子局部位移要跟着中心线一起算**
    （`Tail_2.loc = P3 − P0`），写死成 (0,0,0) 会让三段各自跑到髋部，尾巴散架。
    中心线还要先过一遍 **Catmull-Rom** 再扫管：控制点太稀时直线扫管会留下硬折角。
12. **吻部 deform 的作用角别开太大**。`MUZZLE_ANG = 0.60` 时前突会一路影响到眼角，
    眼睛所在处的面被推走，眼白被埋进脸里只剩一弯月牙；收到 **0.42** 才正常。
13. **预览相机的方位角**：角色面朝 **+Y**，所以"正视图"是方位角 **180°**
    （相机在 +Y），"侧视图"是 **270°**；写成 0° 拍出来的是**背面**。
14. **预览相机距离按传感器宽度算**：70 mm 镜头 + 36 mm 传感器，36 mm 映射到画面的
    **长边**，所以 704×384 的图竖直方向只看到 `dist × 36/704 × 384` mm 高。
    要让 0.85 m 的猴占满画面高度，距离得按这个式子反推（≈3.6 m），别用"看着差不多"。
15. **导出动画片段时 `export_merge_animation='NLA_TRACK'` 必须显式传**
    （默认是 `'ACTION'`）。实测：默认参数下按 track 名合并不生效，
    每个物体会被导成一段独立动画；显式传 `'NLA_TRACK'` 后 7 段片段名才对。
16. **预览的灯光别用冷色环境光**：偏蓝的环境光会把橘色脸盘的饱和度洗掉
    （实测渲染成 0.68/0.51/0.32，参考图是 0.93/0.72/0.48），
    色调分类器会把脸判成"褐色"，对比全盘皆输。用接近白色的环境光 + `Standard` 视图变换。

#### 查"毛刺"的两个手段

| 症状 | 手段 |
| --- | --- |
| 分不清是**几何**坏了还是**着色**坏了 | 把材质临时染成高对比色（脸=品红、眼白=黄、瞳孔=蓝）重渲一张；哪块该是什么色却不是，就是它被谁挡住了 |
| 想知道**谁挡在前面** | 从相机逐像素 `BVHTree.ray_cast()`，打印命中的材质名，画成 ASCII 图 —— 比盯着渲染图猜快得多 |
| 想量化"颅骨从贴片里穿出来" | 渲染一张染色图，数"眼白/瞳孔包围盒里、四周 6 px 都是眼白/瞳孔的品红像素" |

### 2.5 猴头 `m3_monkey_head`（只做头的独立资产）

`assets/models/m3-monkey-head/m3_monkey_head.py` 照 `assets/models/m3-monkey-head/reference.jpg`
（2×2 四视图）复刻**参考图里那只猴的头**，脚本自成一体，**不引用前三只猴的任何代码或参数**。
产出 3 个网格物体：`M3MonkeyHead`（颅骨 + 脸 + 五官 + 呆毛）、`M3MonkeyEar_L`、`M3MonkeyEar_R`。
原点在**颅骨中心**，脸朝 **+Y**，+Z 向上（导出后 Godot 里 **−Z** 向前），
可以直接挂到身体节点的头上。

#### ⭐ 核心做法：整套脸都在"参考图的像素空间"里量

参考图是一张 2×2 四视图拼图，正面那格是 **704×384**，头心在 **(390, 126)**，
**1 px = 1.863 mm**。脚本里所有脸的量（脸盘轮廓、眼睛、瞳孔、高光、眉毛、鼻孔、笑）
**一律用这张图的像素坐标写**，不换算成方位角/仰角：

```python
FACE_CX, FACE_CY, FACE_PX = 390.0, 126.0, 0.001863
FACE_EDGE = [(0, 104), (2, 100), (12, 96), (21, 92), (35, 91), ...]  # 脸盘边界
EYE_L, EYE_R = (351.0, 140.0), (428.0, 140.0)                      # 眼心
EYE_PUPIL_L, EYE_PUPIL_R = (356.0, 142.0), (424.0, 142.0)          # 瞳孔心
BROW_IN_L, BROW_OUT_L = (349.0, 107.0), (333.0, 114.0)              # 眉的两端
MOUTH_BOTTOM = (390.0, 193.0)                                        # 笑的最低点
MOUTH_CORNER_L, MOUTH_CORNER_R = (356.0, 180.0), (424.0, 180.0)      # 笑的两角
```

这样改脸只要改这几个数字，不用重新推导任何角度。

#### 像素坐标 → 颅骨表面的方向：`direction_for()`

参考图的像素要落到**低模颅骨的真实表面**上，所以要反解方向：

```python
def direction_for(x_img, y_img):
    x_w = (FACE_CX - x_img) * FACE_PX
    z_w = (FACE_CY - y_img) * FACE_PX
    # 先二分方位角，直到命中点的 x 对上
    # 再二分仰角，直到命中点的 z 对上
```

⚠️ **不能用"方位角 + 仰角"直接换算高度**：颅骨不是球，同一个仰角方向落点的 z
差很多（实测 el −0.94 落在 z −0.146 而不是 RZ·sin(el)=−0.125），
用 `asin(z/RZ)` 反推仰角会把五官放到下巴底下去。

#### 脸盘边界要转成"长在表面上"的曲线

`FACE_EDGE` 是正面视图里的半边闭合轮廓（眉心尖 → 颞骨峰 → 脸颊 → 下巴）。
直接拿它做正面投影判色，**背面会被一起染成橘色**（正投影分不出前后），
而且侧看会变成一条硬直的竖切口。做法是：

1. 先把边界上的每个像素用 `direction_for()` 解成颅骨上的方向；
2. 按边界走向拆成两张表：眉心→颞骨峰是**上边界**（`|az| → el`），
   颞骨峰→下巴是**侧边界**（`el → |az|`）；
3. 判色时用**面的方向**去查这两张表，并且 `d.y <= 0`（背面）一律算毛。

#### 眉心那道"尖角"要单独画，不能靠判色

参考图额头正中是一道**尖尖的褐毛楔形**（尖在 (390, 103)，上边在第 91 行有 46 px 宽）。
这条楔形**比一个网格棱面还窄**，均匀经纬球 + 逐面判色会把它抹平
（实测整条发际线被拉成一条水平线）。所以楔形单独用**正面像素空间**的三角形来判：

```python
BROW_WEDGE_TIP = (390.0, 103.0)   # 尖
BROW_WEDGE_HALF = 23.0            # 顶边半宽
BROW_WEDGE_TOP = 91.0             # 顶边所在行
```

棱面中心落在楔形三角形内就算褐毛。**网格密度是前提**：楔形高 12 px，
棱面的行高必须小于它（`HEAD_NV = 28` → 行高 ≈ 9 px，`HEAD_NU = 32` → 列宽 ≈ 15 px），
否则一个棱面都套不进楔形里，尖角直接消失。

#### 颅骨不是椭球：用实测的"半径剖面"

参考图的头顶是**压扁的圆顶**，不是球：正面量半宽（颅宽 161 px）得

| 行 (img y) | 仰角 el | 半宽 |
| --- | --- | --- |
| 60 | 0.92 | 41 px |
| 80 | 0.59 | 71 px |
| 100 | 0.32 | 79 px |
| 120 | 0.07 | 80 px |

椭球在这些点上全部偏大或偏小，所以颅骨改用**仰角 → 半宽比例表** `PROFILE`
（`f(el)`，再乘 `RX`）建，侧面另给一个更深的 `RY_BACK`（后脑比脸深）。
下半张脸用同一条曲线但**填得更满**（参考图的脸正面接近一块竖直的平板，
脸越往下越宽，到下巴才收），这样下巴才不会被削成一个尖。

#### 写这只猴时踩到的坑

1. **插值表必须按 x 升序**。`lerp_table()` 假设输入是升序的，
   表写反了会直接失效（整张脸只剩一条窄带）。这种"整块颜色没了"的 bug
   优先怀疑插值表的顺序。
2. **极点的三角扇不能复用极点顶点两次**。`(top, top, v1, v2)` 这种退化四边形会让
   极点变成**孤立顶点**，glTF 导出器报 "Mesh is not valid"。
   极点单独用 `(pole, ring[i2], ring[i])` 的三角扇，纬度带从 j=1 开始。
3. **合并网格会把上色覆盖掉**。`merge_builders()` 重新生成了 mesh，
   之前刷好的 `material_index` 全没了 —— 脸盘又变成一片毛。
   顺序必须是：**先合并、再上色**（`paint_face()` 放在 `merge_builders()` 之后）。
4. **五官要贴到真正的低模面上，不能贴理想球面**。做法：先用 `ray_cast` 打到颅骨的
   **平面**上拿真实表面点，再把每个顶点**抬过当地棱面的深度**
   （`(理想面 - 实际面)·法线 + 0.4 mm`），颅骨才不会从贴片里穿出来，
   贴片自己的轮廓又是干净的 n 边形（不被棱面啃出豁口）。
5. **贴片要分环**（`rings=(1.0, 0.55)`），不然一张大平面会整片陷进颅骨里。
6. **瞳孔要偏内**：参考图两只眼的瞳孔都朝鼻子偏 4.5 px（约 0.008 m），
   高光统一放在 +X 侧（参考图两只眼的高光都在屏幕左边，不是镜像对称的）。
7. ⚠️ **耳朵是"六边形碗"，不是圆滑的椭球**：参考图的正视图里耳廓外面是棕色圆弧、
   里面嵌一块**有直边的橘色五/六边形**，所以耳朵用两组六边形环建：
   碗口（大椭圆 `EAR_RIM_A/B`）→ 橘色耳窝（小椭圆 `EAR_DISH_A/B`）→ 碗心。
   耳朵的朝向**用正/侧两个投影反解**：正面看橘色宽 26 px、侧面看宽 32 px
   ⇒ 碗口法线离 +Y 约 50°，碗心在 (±0.196, −0.061)。
   ⚠️ **碗上的环必须直接在三维里摆**，不能像颅骨那样投影回颅面 ——
   一投影整只耳朵就被拉回脑袋里、橘色耳窝完全看不见。
   耳窝的凹陷要浅（`EAR_SINK = 0.005`）：碗口比耳窝高太多时，正视图里碗沿会把
   耳窝整个挡住，只剩一条橘色细缝。
8. **参考图的正面视图和侧面视图对头部高度给不出同一个答案**（正面量到的下巴更低）。
   以正面视图定脸的比例、侧面视图定前后深度，别拿侧视图的下巴位置去推高度。
9. **预览渲染必须用 `Standard` 视图变换**。默认的 AgX 会把橘色脸盘的饱和度洗掉，
   渲染出来偏灰，和参考图对不上；顺带会让"按颜色分类"的自动比对全部失效。
10. **自动比对时，判"橘色"不能只看 r > 0.82**。参考图的脸有明暗渐变，
    背光那半边是 (0.80, 0.57, 0.38)，按 r>0.82 判会把它当成毛，
    比对结果会出现一大片假的"多出来的橘色"。
    判据要用**色相**：`g > 0.35 and r/g < 1.60`（橘色 r/g≈1.4，棕色 r/g≈1.8）。
11. ⚠️ **耳朵的环不要投影回颅面**（见上面的坑 7）：投影 = 拉回脑袋里，橘色耳窝全没了。
12. **在 Blender 里做"参考图 vs 模型"的自动比对时，`bpy.data.images.load()` 会缓存同路径的旧图**，
    改了模型再渲染，比对图还是旧的 —— 载入前先把同路径的 image 从 `bpy.data.images` 里删掉。
13. **比对渲染要用正交相机**。参考图是平的，用透视相机比会把高处的特征往上推、
    低处的往下拉，比出来全是假差异。

#### 参数速查（都在脚本顶部，单位：像素 / 米）

| --- | --- |
| 颅宽 / 深 / 高 | 0.300 / 0.298 / 0.327 m（含呆毛） |

⚠️ **"两张嘴 / 两只眼"的坑（真踩过）**：关键帧表里"这一帧没点名"的零件**不能被打回静止位**。
第一版每个物体在**每一帧**都打帧（没点名的按静止处理），于是笑嘴在第 3 帧藏进脑袋、第 7 帧又被

换脸通道用 `CONSTANT`（=glTF STEP）插值瞬切，否则过渡那一帧两张嘴会各露一半。

⚠️ **表情件怎么"藏"**：不用 scale（本项目要求 scale 恒为 1），而是**整块平移到颅骨内部**

`DSMonkeyMouthLaugh` / `DSMonkeyMouthFear` / `DSMonkeyEyeShut_L|R` 都停在颅骨里，
所以默认露出的就是中性脸。**新加一条：这类"藏在模型内部"的零件，`node.translation` 在静止态不为 0，
但那不是隐藏缩放，§6.7 的 scale 校验照样全 1。**

#### 写这只猴时踩到的坑

1. ⚠️ **贴片的投影空间必须和 BVH 一致**。颅骨网格是按"枢轴局部坐标"存的，而射线原点写的是世界坐标的
   头心 —— 结果眼白/眉毛/鼻孔全被投到**错误的部位**（眼睛跑到额头、眉毛飘在轮廓外）。
   修法：`make_bvh(ob, offset)` 把网格搬到世界空间再建 BVH。
2. ⚠️ **发际线用"逐棱面上色"时，列数决定能不能做出那道 V**。32 列时楔形被抹成一条横带；
   40 列 + 表里正中压到 el 0.115 才读得出来。**但列数再多也会有台阶** —— 这是平面着色的本性，
   参考图本身也是低模平面着色，所以接受它，别试图用"浮一层脸盘壳"去救：
   壳的粗面会**切进颅骨棱面**，渲染出来是颅骨从脸里穿出来的碎三角（实测过，lift < 2 mm 必翻车）。
3. ⚠️ **耳朵不要加"补缝柱"**。耳根埋进颅骨就够了；加一根从耳背插进脑袋的管子，
   管径 30 mm 会从脸颊**顶出一个棕色包**。
4. ⚠️ **拍手要把手凑到中线，靠的是 Y 轴内旋，Z 轴做不到**。肩宽 0.284 m、臂长 0.2 m，
   手要到 x=0 必须内旋 70° 以上；`CLAP_CLOSED` 是脚本里**扫出来**的（还要检查肘部在躯干外，
   否则手臂会埋进胸腔）。实测闭合掌面间距 **0.0013 m**、张开 **0.0835 m**。
5. ⚠️ **坐姿的髋高不是随便填的**。参考图里骨盆是**坐在地上**的（髋枢轴只离地 0.067 m），
   坐高因此是 0.68 m；先摆角度再让地面兜底会把整个人顶起来，坐高变成 0.80（比例全错）。
   正确顺序：定髋高 → 用**两骨 IK** 反解腿角把脚掌落到地面 → 再用 `ground` 兜 1 mm。
6. ⚠️ **预览灯光别开太亮**。参考图的受光毛色顶到 0.64 sRGB；太阳 3.1 + 环境 0.8 会把它洗到 0.85，
   按色相分类的自动比对就会把毛判成"脸"（整颗头都被算成橘色）。现在太阳 2.15 / 环境 0.42。
7. **左右镜像只在作者层做一次**。`arm()/leg()` 里 `ry/rz` 乘 `sgn`，IK 算出来的欧拉角**直接 `add()`**，
   不要再乘一次符号，否则左半边的姿态会被镜像两次。
8. **Godot 导入自检**：headless 导入后根节点 `ds_flash_lowpoly_monkey`、`scale = (1,1,1)`，
   `AnimationPlayer` 里 8 条片段、每条 **22 条轨道**（眼睛/瞳孔这类不动的节点被
   `remove_immutable_tracks` 剔掉），24 个 `MeshInstance3D`。

#### 做法速查

| 部件 | 做法 | 关键点 |
| --- | --- | --- |
| 躯干 / 胯 | **10 列车削**（`lathe`，剖面 `(z, rx, ry)` 逐行量） | 蛋形：腰 0.076 → 胸 0.103 → 肩线往回收 0.046（顶环塞进颅骨底面） |
| 肚皮 | **逐面换材质**（`torso_mat`） | 六边形排布：`4 列`（弦长 0.166）3 行 + `2 列` 收口 2 行 |
| 四肢 | **关节球 + 锥台**（6 棱） | 肩/肘/胯/膝各一对球，球 = 管径 ×1.08~1.18，管端埋进球里 |
| 手脚 | **矩形截面放样**（`loft` + `rect_pts`） | 脚底严格 z = 0（五段截面底高全 0），脚掌 / 手掌用 `DSBody_tan_deep` |
| 尾巴 | **Catmull-Rom 大钩 → 等弧长切 4 段 → 每段走曲线子路径** | 枢轴 = 切分点，`location = 段首 − 父段首` |
| 预览 | 四视图 + **与参考图叠加**（正交、550 px/m） | 抓「比例漂了」比肉眼快 |

#### 写这只身体时踩到的坑

1. ⚠️ **肚皮不能用「贴片」**（试过 4 轮，全部翻车）：
   ① `lathe` 的格子**不是平面**（rx≠ry、上下半径也不同），按「理想椭圆面 + 径向抬高」
   建的贴片会被棱面啃出碎斑；② 改沿**真实法线**抬高也一样 —— 相邻采样点落在不同棱面上，
   两块面之间的弦切进躯干 **2.65 mm**（BVH 实测），渲染出来是「被咬掉几块」；
   ③ 抬高到 3.5 mm 能盖住，但边缘就浮起来了。
   **结论：分色边界落在网格边上（逐面判色），和共用头的脸盘是同一种做法** —— 0 成本、不会翻车。
   代价是边界只能是「2 列 / 4 列」两档，正视看是六边形而不是圆角椭圆，低模风格里可以接受。
2. ⚠️ **肩球别放在躯干顶面上**。`z = 0.264` 时球的顶会冒出躯干轮廓，正面看是**两个尖角**；
   肩枢轴要落在躯干**侧面**（`(±0.090, 0, 0.238)`），球一半在躯干里、一半露在外面。
3. ⚠️ **手臂必须外张到「前臂 × 躯干 = 0」**（`audit_clearance()` 打印，见下）。
   竖直垂下的手臂会在肘部整段埋进躯干，正面看就是一块板；肘要外移到 `x ≈ 0.124`
   才让得出一条可见的缝。
4. ⚠️ **尾巴要「先切弧、再在弧上扫管」**。第一版把等弧长采样的 4 段各扫一段**直线**，
   侧视图里能数出 3 个硬折角；段内必须走**曲线子路径**（每段再重采样 4 环）。
5. ⚠️ **父级的局部位移 = 世界枢轴差**，不能图省事写 `(0,0,0)`。肚皮那次写 `(0,0,0)`，
   整片被移到躯干枢轴上（y 少了 0.09），直接消失在身体里。
6. **脚枢轴放在踝关节**，网格的脚底仍在 z = 0 —— 枢轴写 `(x, 0, 0)` 会把整只脚抬起 3.2 cm
   （`assert min z < 1.5 mm` 抓到的）。
7. **预览拼图的缓冲区方向**：`load_rgba` 统一翻成「自上而下」、`save_rgba` 再翻回「自下而上」。
   只翻一头的话，四视图是**倒的**（第一版就是，sanity check 全靠肉眼才发现）。

## 4. 原点（pivot）约定

原点决定 Godot 里 `position` 的含义，必须按类型统一：

| 类型 | 原点位置 | 生长 / 朝向 |
| --- | --- | --- |
| 树木、草 | **根部地面中心 (0, 0, 0)** | 沿 **+Z** 生长（导出后在 Godot 沿 +Y） |
| 悬挂物（香蕉） | **蒂（与果轴相连的一端）** | 从原点向 **−Z** 生长并弯向 +X；导出后向 −Y 垂下 |
| 地形 / 岛 | **岛屿中心，海平面 z = 0** | — |
| 道具 / 可拾取物 | 放在"被握持 / 被放置的面"的中心 | — |

导出前必须把所有对象的世界变换烘进网格并归零：

```python
bpy.ops.object.transform_apply(location=False, rotation=True, scale=True)
for ob in mesh_objects:
    ob.data.transform(ob.matrix_world)   # 世界变换烘进网格
    ob.matrix_world.identity()           # 原点回到 (0,0,0)
```

## 6. 自检清单（每次生成后逐条确认）

1. `min(z) ≈ 0`：根部 / 落地面贴地（±0.02 m）。
2. 尺寸落在 §2 基准的 ±2% 内；若确实要改款，**同时**更新 §2 表格与依赖它的 Godot 组件参数。
3. 所有物体 `scale == (1,1,1)`、`rotation == 0`（已 apply）。
4. `.glb` 用 `export_yup=True` 导出，Godot 导入保持 `apply_root_scale=true / root_scale=1.0`（现有 `.import` 文件已是如此）。
5. 打印的高度 / 跨度与 §2 表格一致，把实测数字留在脚本输出里。
6. 顶点色资产（草、香蕉树）颜色为**线性空间**（先做 sRGB→linear），否则 Godot 里会发白发灰。
7. **导出节点里不含非 1 的 `scale`**（见下方自动校验）；这条同时兜住"约束/参考物没清干净"的情况。
8. **棱面质量（低多边形"边缘干净"的关键）**：形体必须由平面切割得到，每刀都先在副本上验收，
   门槛见 `low_poly_rock.py`：棱面紧凑度 `4πA/P² ≥ 0.46`（挡掉又长又窄的刀面 sliver）、
   棱面面积 `≥ 0.05 m²`、最短棱边 `≥ 0.09 m`、三角面最小角 `≥ 4°`（只兜退化）。
   量的是**棱面**不是三角面：同一棱面内三角形共面同色，面内细长三角不可见。
9. **顶点色按棱面上色，不按三角面上色**：同一平面的所有三角形必须同色，否则面内碎切会渲染成脏斑，
   棱线也糊成一团（`low_poly_rock.py` 的 `plane_groups()` 就干这件事）。

### 尺寸审计（一条命令核对全部资产）

```bash

import json, struct, glob
for p in sorted(glob.glob("assets/**/*.glb", recursive=True)):

    lo = [min(js["accessors"][i]["min"][k] for i in idx) for k in range(3)]
    hi = [max(js["accessors"][i]["max"][k] for i in idx) for k in range(3)]
    print(f"{p:68s} {[round(hi[k]-lo[k], 2) for k in range(3)]}")

python3 - <<'EOF'
```

当前实测：`assets/models/**` 全部为 `OK`；
唯一的例外是外部资产 `assets/island/sky-island-basic.glb`——它的 5 个节点自带 `scale = 0.01`
（原作者用节点缩放把模型缩到 0.01 倍）。这正是 §1.1 说的反面例子：**缩放藏在节点里，网格本身是 100 倍大小**，

### 想要"改一处、全体同步"时怎么办

不引入约束，改用**脚本内的单一常量源 + 断言**，效果等价且不污染导出：

```python
# 在共享模块里定义唯一基准，各脚本 import 它
SIZE_REF = {"grass_m": 0.7, "banana_tree_tall_m": 4.77, "banana_m": 0.55}

# 每个脚本收尾时断言，尺寸漂了就报错，而不是悄悄变大变小
assert abs(measured_height - SIZE_REF["banana_tree_tall_m"]) < 0.02, \
    f"高度漂了：{measured_height:.3f} != {SIZE_REF['banana_tree_tall_m']}"
```

这比约束更强：约束只同步"比例系数"，这里同步的是**绝对米数**，正是本项目要的东西。

## 8. 目录与产物约定

```
assets/
  models/<资产名>/
    <name>.py            # 生成脚本（唯一事实来源，提交。文件名不一定要叫 <name>)
    <name>.blend         # Blender 源文件（提交）
    <name>.glb           # Godot 用资产（提交）
    <name>_preview.png   # 预览图（提交，便于 review）
    <name>_anim.png      # 可选：带内置动画的接触表（只有含动画的资产才有）
  models/_shared/        # 跨资产的共享构建代码（不是一个资产，没有 .glb）
    ruin_kit.py          # 废墟石墙的唯一实现 + 调色板 + 网格工具 + 预览机位
  island/                # 主地图地形与形状数据
    jurassic_island.py         # 地形生成器
    jurassic_island_shapes.py  # 烘焙的形状数据（由脚本导入，勿手改）
```

- 一个资产一个目录，脚本内路径用 `os.path.dirname(os.path.abspath(__file__))` 派生，**不要**写死绝对路径
  （`models/apple-tree/low_poly_tree.py` 里遗留的绝对 `OUT_DIR` 属于待清理项）。
- 随机造型必须固定 `random.seed(...)` / 固定噪声种子，保证可复现。
- 预览图渲染用于人眼校验比例：至少一张带地面的正视 / 3/4 视图。
- **同一个构件被两个以上资产用到时，抽到 `models/_shared/`，不要复制粘贴。**
  典型：大门两翼的矮墙与 `low_poly_ruined_wall` 必须是同一堵墙，复制一份必然会在
  基座高度 / 砖缝 / 压顶上慢慢跑偏，拼接处就露出台阶。
- 用 Blender MCP 工作时：先 `get_scene_info` 确认场景，再用 `look` 看图核对比例；`execute_blender_code`
  里读引擎 / 枚举一律**按 type 查节点**、写进 `try/except TypeError`，不要写死本地化名称。
